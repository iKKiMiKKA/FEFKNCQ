# 用户输入容错：三种素材模式与降级规则

用户可能只丢来一张图、两张图，甚至图与需求不完全匹配。先判定模式，再决定每格提示词里
"身份/风格参考"与"姿态参考"分别取自哪里。**任何模式下，姿态与坐标一律以官方示例帧为准**，
OC 素材只提供长相、配色、线条风格。

## 模式判定

| 模式 | 用户提供 | 身份/风格来源 | 姿态来源 |
|---|---|---|---|
| A（最佳） | 1 张 OC 头像 + 1 张 OC 脚 | 头像定五官/配色，脚定趾形/爪垫/饰物 | 官方 `generic.png` 的 11 个爪格 + 14 个表情格 |
| B | 1 张 OC 全身图 | 从全身图裁出头部与脚部作为两张参考 | 同上 |
| C | 1 张 OC 头像 + 1 张"手"的图 | 头像定五官；手部图**仅**借用线条、配色、指甲/饰物风格 | 同上；脚的解剖按示例帧 + 用户文字描述 |

### 模式 B 细则

- 用图像工具裁出头部（用于 14 个表情格）与脚部（用于 11 个爪格）；裁图只是参考，不是最终切片。
- 若全身图里脚被遮住、穿鞋、角度不可辨：脚部结构按官方示例 11 帧推导，鞋/袜/配色按用户文字描述补充；在 `oc_profile.md` 里明确记录"脚部为推导，非参考图实测"。
- 全身图若同时含有多种表情或动态，优先取最中性的一张作身份基准。

### 模式 C 细则（重要，避免"手变脚"事故）

- 手**不能**当作脚的解剖依据：趾数、趾序、脚掌比例、受力面都不同。
- 手部图只用于：线条粗细、描边颜色、上色风格、指甲/戒指/纹身等可迁移特征。
- 脚的形状以官方示例 11 帧为准；若用户希望"手的特征"体现在脚上（例如同款指甲油），只能迁移颜色与装饰，不能迁移骨骼结构。
- 向用户说明这一限制，并建议补一张脚部参考；用户不补则按上述规则继续，不阻塞流程。

## 统一索取/补齐的 OC 描述字段

在生成前整理成 `oc_profile.md`（本地工作文件），每条逐格提示词都复述固定项：

```
名称：（用于 ZIP 的 giant.name）
物种/种族：
主色 / 辅色 / 描边色：
脚：左或右、趾数、爪垫形状、有无指甲/鞋/袜、特殊记号
脸：脸型、耳形、瞳色、发型、项圈/斑点/妆容
画风：线条粗细、上色方式、是否有阴影
禁止项：文字、边框、背景板、水印
```

缺失字段用最保守的默认值（"与参考图一致"），并在交付说明里标注哪些是假设。

## 降级矩阵

| 情况 | 处理 |
|---|---|
| 完全没有参考图，只有文字描述 | 按文字生成角色，姿态仍取示例帧；交付时标注"形象为文字推导" |
| 只有头像，没有脚 | 脚按示例姿态 + 文字描述生成；建议后续补图迭代 |
| 只有脚，没有头像 | 头像按脚的配色/画风推导一张中性脸；明确标注为假设 |
| 生图模型不支持透明 PNG | 指定纯色底（纯白/纯绿/品红），保持默认 `--bg auto` 自动估色去背；估色失败才显式 `--bg white/green/magenta`。禁止直接贴白底方块（`plate:*` 会判 FAIL） |
| 生图帧不是 8-bit 非隔行 PNG | 先转成 8-bit PNG 再放进 `frames/`；`read_png` 不支持 16-bit / 隔行 / WebP，`build_sheet.py` 会记 error、`validate.py` 判 FAIL |
| 某几格生成失败或明显崩坏 | 缺帧会沿 `REUSE_MAP` 自动复用并取同组基准帧，报告标 `reused:*` / `baseline:*`；后续单独重画这几格再合成，无需改参数 |
| 相邻帧突变 | 只重画突变帧，以相邻两帧作参考图，不整组重抽 |

## 与"直接能玩"的关系

- 本文件解决的是**素材不足时的容错**，不降低交付标准：`build_sheet.py` + `validate.py` 必须跑通。
- 素材越不完整，C1–C11 连贯性约束越要写进每一条提示词，尤其 C1（同一只脚）、C6（同一张脸）与 C11（脚底贴格底）。
