# 用户输入容错：四种素材模式与降级规则

用户可能只丢来一张图、两张图，甚至图与需求不完全匹配。先判定模式，再决定每格提示词里
"身份/风格参考"与"姿态参考"分别取自哪里。**任何模式下，姿态与坐标一律以官方示例帧为准**，
OC 素材只提供长相、配色、线条风格。游戏只按坐标切片、不识别脚或手，因此**用户明确说
"用手"时按手生成，不再限定为脚**。

## 模式判定

| 模式 | 用户提供 | 身份/风格来源 | 姿态来源 |
|---|---|---|---|
| A（最佳） | 1 张 OC 头像 + 1 张 OC 脚 | 头像定五官/配色，脚定**鞋袜款式**/趾形/爪垫/饰物 | 官方 `generic.png` 的 11 个爪格 + 14 个表情格 |
| B | 1 张 OC 全身图 | 从全身图裁出头部与脚部作为两张参考 | 同上 |
| C | 1 张 OC 头像 + 1 张"手"的图，**未**说要用手 | 头像定五官；手部图**仅**借用线条、配色、指甲/饰物风格 | 同上；脚的解剖按示例帧 + 用户文字描述 |
| **D（手模式）** | 用户**明确**说"用手 / 手掌 / 手拍 / 不要脚" | 按用户意图生成**真正的手**（或参考图里的**同款手套**）：五指、指序、指甲/掌心缝线、手腕 | 同上，动作时间线不变：抬手→触地→压扁 |
| **E（仅角色名）** | 仅动漫/游戏角色名或文字描述，**未附任何参考图** | 由角色名推导：采用该 IP **最经典、最具标志性的形象**，还原发型、脸型五官、身材比例/体型、服饰款式与配色、标志性配件 | 同上（官方示例帧） |

> C 与 D 的区别只看**用户有没有明确要求用手**：只发来手部参考图不等于手模式。
> **E 与 A/B/C 的区别只看"有没有参考图"**：用户只给角色名/文字、没给图，就按模式 E 用经典造型生成；一旦用户补来参考图，以图为准、退回对应模式。

### 鞋袜与手套（所有模式通用，优先级高于"光脚/光手"）

参考图里若**穿鞋、穿袜或戴手套**，一律按鞋和手套画，不要执着于光脚/光手：

- **必须保留同款**：鞋型、鞋底纹路、鞋带/袜子/饰物、手套材质/掌心缝线/腕饰，
  在 11 个爪格中完全一致；不得脱掉、换款、换色，也不能只在部分帧出现。
- **固定项换成鞋/手套**：写进 `oc_profile.md` 的 `{{FOOT_FIXED}}` 以鞋型或手套款式为准；
  趾数、趾序、爪垫、掌纹、指甲只在**裸露可见时**才约束，不要为了凑"五趾/五指"把鞋或手套画破。
- **露脚底改为露鞋底/手套掌面**：`front_0` 的"露完整脚底"在穿鞋时改为鞋底（纹路、鞋跟），
  戴手套时改为手套掌面（掌心缝线/压纹）；绝不能为了露脚底把鞋或手套脱掉。
- **污渍落在鞋底/掌面**：C3 的压扁与污渍只增不减改为鞋底泥痕/手套掌面磨痕。
- C1/C5/C11 与 `ground:*` / `leg:*` 全部照常生效；腿仍是实体填充（穿鞋时可为裤腿/袜筒）。

### 模式 B 细则

- 用图像工具裁出头部（用于 14 个表情格）与脚部（用于 11 个爪格）；裁图只是参考，不是最终切片。
- 若全身图里脚被遮住、角度不可辨：**先按参考图里的鞋/袜画**（见「鞋袜与手套」）；只有完全看不清鞋型时才按用户文字描述推导，并在 `oc_profile.md` 里标注"鞋型为推导，非参考图实测"。
- 全身图若同时含有多种表情或动态，优先取最中性的一张作身份基准。

### 模式 C 细则（只有手部参考图，避免"手变脚"事故）

- 手**不能**当作脚的解剖依据：趾数、趾序、脚掌比例、受力面都不同。
- 手部图只用于：线条粗细、描边颜色、上色风格、指甲/戒指/纹身等可迁移特征。
- 脚的形状以官方示例 11 帧为准；若用户希望"手的特征"体现在脚上（例如同款指甲油），只能迁移颜色与装饰，不能迁移骨骼结构。
- 向用户说明这一限制；若用户改口"那就用手"，立即切换到模式 D，不再套用本节的脚约束。

### 模式 D 细则（手模式）

- **11 个爪格全部画手**，不是脚，也不是"长了脚趾的手掌"；裸露时固定五指、指序、指甲、
  掌纹、掌根、手腕；参考图戴手套时 11 格一律画**同款手套**，固定款式、材质、掌心缝线/
  压纹与腕饰，不脱不换款，五指/掌纹只在裸露可见时才约束（见上文「鞋袜与手套」）。
- 前后爪关系：`front_*` 是一只手的连续下落，`back_*` 是**同一角色另一只手**（远景略小、略淡），
  不得混用一只手一只脚。
- **C11 不变**：手掌最底部像素必须紧贴格子底边 `y=255`，脚本仍会裁剪透明边并底对齐，
  `validate.py` 的 `ground:*` 照常拦截；否则游戏里同样会出现"手悬空却已拍死小人"。
- C1/C2/C3/C4/C5 按手等价执行：同一只手、左右固定、指数与指甲不变、掌面污渍只增不减。
- 提示词替换表与 `{{FOOT_FIXED}}` 的填法见 `references/prompts.md` 第 2 节与第 6 节；
  坐标、首版 10 张必生格、复用映射、ZIP/PNG 交付流程**完全不变**。

### 模式 E 细则（仅角色名 / 纯文字，无参考图）

用户只说了动漫或游戏角色的名字（或一段文字描述），**没有附任何参考图**时适用：

- **采用最经典、最具标志性的形象**：取该角色最广为人知、辨识度最高的造型，而非冷门版本、
  二创或混搭。发型、脸型五官、身材比例/体型、服饰款式与配色、标志性配件（如护额、披风、
  武器）都必须尽量与原型一致。
- **写入固定项**：把上述特征逐条写进 `oc_profile.md` 的 `{{OC_DESC}}` / `{{FACE_FIXED}}` /
  `{{FOOT_FIXED}}`，并额外注明「形象依据：<角色名> 的经典造型」；**身材/体型**也作为固定项
  锁定（见「统一索取/补齐的 OC 描述字段」），避免生成时漂移。
- **姿态仍按官方示例帧**：本模式只决定长相/配色/风格，不改变任何坐标、动作时间线或必生格。
- **有多个经典造型时选最标志性的**：例如同一角色不同时期，取最被大众认知的那一版；并在
  首次交付时明确告诉用户「采用了 X 的经典造型（如：XX 时期）」，方便他纠正或指定版本。
- **用户后续提供具体参考图时，以参考图为准**，覆盖角色名推导结果，退回模式 A/B/C 处理。
- 鞋袜/手套同样从经典造型推导（见「鞋袜与手套」）：若角色经典造型穿鞋/戴手套，按同款画。

## 统一索取/补齐的 OC 描述字段

在生成前整理成 `oc_profile.md`（本地工作文件），每条逐格提示词都复述固定项：

```
名称：（用于 ZIP 的 giant.name）
物种/种族：
主色 / 辅色 / 描边色：
肢体（脚模式）：左或右、趾数/爪垫（裸露时）、鞋/袜类型与鞋底纹路、鞋带/饰物、特殊记号
肢体（手模式 D）：左或右、五指指序/掌纹（裸露时）、手套类型与掌心缝线、戒指/腕饰、特殊记号
脸：脸型、耳形、瞳色、发型、项圈/斑点/妆容
身材/体型：高矮胖瘦、头身比、躯干与四肢比例（角色名模式须锁定标志性体型）
画风：线条粗细、上色方式、是否有阴影
禁止项：文字、边框、背景板、水印
```

「名称」会写进 ZIP 的 `settings.json` 的 `giant.name`（`build_sheet.py --name`），
没给名字就用模板默认值 `MY OC`，不阻塞流程。
缺失字段用最保守的默认值（"与参考图一致"），并在交付说明里标注哪些是假设。

## 降级矩阵

| 情况 | 处理 |
|---|---|
| 完全没有参考图，只有角色名/文字描述（模式 E） | 采用该角色**最经典、最具标志性的形象**，还原发型、脸型五官、身材比例/体型、服饰配色、标志性配件；姿态仍取示例帧；交付时标注「形象依据：<角色名> 经典造型」 |
| 只有头像，没有脚 | 脚按示例姿态 + 文字描述生成；建议后续补图迭代 |
| 只有脚，没有头像 | 头像按脚的配色/画风推导一张中性脸；明确标注为假设 |
| **用户明确说"用手 / 不要脚"** | **切到模式 D**：11 个爪格全部生成真正的手，不再限定脚；坐标与流程不变 |
| 参考图穿鞋 / 穿袜 / 戴手套 | 按鞋和手套画，不脱不只画光脚/裸手；鞋型/手套款式写入 `oc_profile.md` 作为固定项，见上文「鞋袜与手套」 |
| 生图模型不支持透明 PNG | 指定纯色底（纯白/纯绿/品红），保持默认 `--bg auto` 自动估色去背；估色失败才显式 `--bg white/green/magenta`。禁止直接贴白底方块（`plate:*` 会判 FAIL） |
| 生图帧不是 8-bit 非隔行 PNG | 先转成 8-bit PNG 再放进 `frames/`；`read_png` 不支持 16-bit / 隔行 / WebP，`build_sheet.py` 会记 error、`validate.py` 判 FAIL |
| 某几格生成失败或明显崩坏 | 缺帧会沿 `REUSE_MAP` 自动复用并取同组基准帧，报告标 `reused:*` / `baseline:*`；后续单独重画这几格再合成，无需改参数 |
| 相邻帧突变 | 只重画突变帧，以相邻两帧作参考图，不整组重抽 |

## 与"直接能玩"的关系

- 本文件解决的是**素材不足时的容错**，不降低交付标准：`build_sheet.py` + `validate.py` 必须跑通。
- 素材越不完整，C1–C11 连贯性约束越要写进每一条提示词，尤其 C1（同一只脚/手）、
  C6（同一张脸）与 C11（脚掌/手掌贴格底）。
