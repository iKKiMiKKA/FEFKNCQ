# 逐格生图提示词（首版 C 档 + 渐进补细节）

**绝不让图像模型一次输出整张 1024×1024 精灵表**。首版只生成 **8 张必生图**，
其余 18 格由 `scripts/build_sheet.py` 按 `scripts/layout.py:REUSE_MAP` 自动复制同组基准帧。
跑通能玩之后，agent 应主动询问用户是否需要补更多细节；补细节只需往 `frames/`
多放几张 `<帧名>.png` 重新合成，**不需要改任何配置**。

## 1. 首版 8 张必生格

| 文件 | 编号 | 用途 |
|---|---|---|
| `front_0.png` | P01 | 前爪：抬起最高（空中姿态基准） |
| `front_3.png` | P02 | 前爪：刚触地（地面姿态基准） |
| `front_5.png` | P10 | 前爪：最大压力（高压基准） |
| `back_0.png` | P03 | 后爪：远景基准 |
| `normal_1.png` | F03 | 表情：低 ego（跨度第 1 档） |
| `normal_3.png` | F07 | 表情：中 ego（跨度第 2 档） |
| `normal_5.png` | F11 | 表情：高 ego（跨度第 3 档） |
| `endscreen.png` | E01 | 结算横幅 |

**表情三档必须"跨度大"**：`normal_1` / `normal_3` / `normal_5` 之间要有明显可见的
情绪差异（平静 → 明显愉悦 → 陶醉满足），不要只改几根线条。其余低档帧复用 `normal_1`，
中高档复用 `normal_3` / `normal_5`，这样玩家仍能看出 ego 变化。

## 2. 占位符

| 占位符 | 内容 |
|---|---|
| `{{OC_DESC}}` | `oc_profile.md` 里的角色长相、配色、物种、画风 |
| `{{FOOT_FIXED}}` | 固定脚部特征：左右、趾数、趾序、爪垫、指甲/鞋袜、记号、描边色 |
| `{{FACE_FIXED}}` | 固定脸部特征：脸型、耳形、瞳色、发型、项圈/斑点、描边色 |
| `{{STYLE}}` | 线条粗细、上色方式、阴影方向 |
| `{{REF}}` | 已生成的同组基准帧（作为参考图上传给模型） |

## 3. 通用前缀（每条提示词都要带）

```
为 2D 手绘游戏生成【单张独立素材图】，只画一个主体，不要越出画面。
角色设定：{{OC_DESC}}。画风：{{STYLE}}。
背景：纯透明 PNG；若无法输出透明，请用纯白色（#FFFFFF）平铺背景，主体外不要有任何渐变、阴影或环境。
【爪格构图·最重要】脚掌最底部必须紧贴画面底边，脚底与底边之间不得留任何透明空隙（≤2px）；
腿从脚掌向上延伸并超出画面顶边（腿在顶边被裁断）。透明留白只允许在脚的上方与左右两侧，
绝不允许出现在脚底下方。禁止把整只脚居中摆放，禁止在脚下画地面、影子或留白。
【表情格构图】头像居中，占画面约 80%，上方留少量透明边。
严格禁止：文字、水印、边框、圆角框、UI 元素、投影、多余人物、多余肢体、第二只脚、镜像翻转、随机花纹变化。
构图比例：爪格为竖版 5:8，表情格为正方形 1:1，结算横幅为横版 2:1。
参考图 {{REF}} 只用来对齐长相与同组基准姿态；禁止改变 {{FOOT_FIXED}} / {{FACE_FIXED}} 中任何固定特征。
```

> 游戏把爪格底边当作脚底位置，碰撞判定完全不看图片内容；脚底留白会让脚看起来悬空、
> 小人却已被踩死。脚本层还会再自动裁剪+底对齐兜底，但提示词必须先把这件事说清楚。

## 4. 通用负面提示词

```
文字, 字母, 水印, 边框, 背景板, 立体 3D, 照片质感, 多只脚, 左右翻转, 趾数变化,
新增饰品, 换脸, 换发型, 换瞳色, 换画风, 突然的视角切换, 突然出现的污渍,
突然消失的污渍, 血腥特写, 越界裁切, 白底方块, 灰色棋盘格,
脚底留白, 脚掌悬空, 整只脚居中, 脚下空隙, 脚下地面, 脚下阴影, 腿在画面内收尾
```

## 5. 连贯性固定句（每条结尾追加）

```
必须与同组其它帧构成同一动作的连续帧：同一只脚/同一张脸、固定左右与视角、
{{FOOT_FIXED}} / {{FACE_FIXED}} 完全不变；只允许本次指定的姿态或表情变化；
压扁程度与污渍只增不减；不得突变。
```

## 6. 八条必生格提示词

| 文件 | 本格专属描述 |
|---|---|
| `front_0.png` | `{{OC_DESC}} 的{{FOOT_FIXED}}，侧视，脚尖朝画面左，脚跟抬起离地最高，可见脚底边缘。基准帧，干净无污渍。` |
| `front_3.png` | `同一只脚刚触地，转为正面压平的形态，脚趾朝左，轮廓舒展，压力≈0。与 {{REF}} 是同一只脚的下落连续帧。` |
| `front_5.png` | `同一只脚最大压力，脚掌最扁，趾缘与脚底污渍最多（在全部爪格中最多）。` |
| `back_0.png` | `{{OC_DESC}} 的另一只后脚（同一双脚），远景透视略小略淡，{{FOOT_FIXED}} 不变，无压力、干净。` |
| `normal_1.png` | `{{OC_DESC}} 的头像，{{FACE_FIXED}}，正面。低 ego：平静、略困、眼神平淡、嘴角平直。这是三档中最低一档，情绪要明显偏低。` |
| `normal_3.png` | `同一张脸，只改眉眼嘴。中 ego：明显愉悦、眼睛更亮、嘴角明显上扬。与 {{REF}}（低档）相比情绪差异要清楚可见。` |
| `normal_5.png` | `同一张脸，只改眉眼嘴。最高 ego：陶醉、眯眼、满足到近乎得意，可加脸红。与 {{REF}}（中档）相比情绪差异要清楚可见；三档之间必须形成明确跨度。` |
| `endscreen.png` | `{{OC_DESC}} 与小人（tinies）在一起的横版收尾插画，用作结算页顶部横幅；横版 2:1，主体居中，可以有背景色（此格允许不透明），但禁止任何文字、边框、UI、水印。` |

> 爪格三条必须看起来是同一只脚从"抬起 → 触地 → 压扁"的连续动作；
> 后爪要与前爪同属一个角色，不能变成手、鞋或另一物种。

## 7. 复用映射（首版自动生效，无需生成）

| 复用格 | 复制自 | 代价 |
|---|---|---|
| `front_1`、`front_2` | `front_0` | 抬爪过程不做渐变 |
| `front_4` | `front_5` | 中压与高压同图 |
| `back_1..4` | `back_0` | 后爪不随压力变化（这些帧本就极难出现） |
| `normal_0`、`normal_2` | `normal_1` | 低 ego 段无细变化 |
| `normal_4` | `normal_5` | 高 ego 段无细变化 |
| `excite_0..5` | 对应 `normal_*` | **兴奋列与常态列相同，击杀时表情无变化** |
| `tired_0`、`tired_1` | `normal_1` | 疲惫状态用低档表情，两帧无眨眼差 |

首版因此会损失三类反馈：兴奋表情、疲惫动画、后爪压力变化。
这三类正是"导入后询问用户是否补细节"时的优先候选。

## 8. 生成批次与并发

1. **默认尝试并发**：把 8 张必生格的提示词一次性提交给生图通道（若支持批量/并发），
   用并发缩短等待时间。
2. **回退规则**：若生图通道不支持并发、报并发限制或并行结果互相串图，
   立即改为逐格串行生成，**其余流程一律不变**（不改合成、校验、导入步骤，也不重新设计提示词）。
3. 串行时顺序：先 3 张爪 + 1 张后爪 → 3 张表情（以 `normal_1` 为基准，其余两张以它为参考）→ 横幅。
4. 输出统一命名 `frames/<cell>.png`，且必须是 **8-bit 非隔行 PNG**（RGBA/RGB/调色板均可）。
   尺寸不精确没关系：爪格由 `build_sheet.py` 裁掉透明边后**底对齐**贴入，表情格与横幅等比居中贴入。
   各帧尽量都用 5:8 竖版，避免包围盒比例差异过大导致脚被独立缩放。
5. 模型不支持透明输出时统一指定纯白底，合成保持默认 `--bg auto`（自动估背景色）；
   仅当自动估色失败才显式 `--bg white/green/...`。不要混用多种底色。

## 9. 补细节（用户确认后再做）

按"可见收益 / 成本"排序，用户可任选若干项，每补一项就多生成对应文件：

| 优先级 | 补哪些格 | 收益 |
|---|---|---|
| 1 | `excite_3`（或 `excite_1`/`excite_5`） | 恢复击杀时的兴奋反馈 |
| 2 | `tired_0` + `tired_1` | 恢复疲惫眨眼动画 |
| 3 | `front_1`、`front_2` | 抬爪过程更连贯 |
| 4 | `back_2`、`back_4` | 后爪压力变化 |
| 5 | `normal_0`、`normal_2`、`normal_4` | 表情过渡更细腻 |
| 6 | 其余 `excite_*` | 完整兴奋列 |

补完后重跑：

```
python scripts/build_sheet.py --frames frames/ --base generic.png --out custom.png --bg auto
python scripts/validate.py --sheet custom.png --base generic.png --report custom.report.json
```

`validate.py` 的 FAIL 必须修完再导入；WARN 逐条目检。
`build_sheet.py` 的 report 会标出每格是 `generated` 还是 `reused:<源格>`，便于核对补画是否生效。
