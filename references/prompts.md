# 逐格生图提示词（首版 C 档 + 渐进补细节）

**绝不让图像模型一次输出整张 1024×1024 精灵表**。首版生成 **9 张必生图**，
其余 17 格由 `scripts/build_sheet.py` 按 `scripts/layout.py:REUSE_MAP` 自动复制同组基准帧。
跑通能玩之后，agent 应主动询问用户是否需要补更多细节；补细节只需往 `frames/`
多放几张 `<帧名>.png` 重新合成，**不需要改任何配置**。

> 表情走两条线：**无击杀时**（`normal` 列，按 ego 等级显示）复用同一张平静脸，头像不随
> ego 升级而变；**每次击杀得分后约 0.5 秒**（`excite` 列）才闪现明显不同的兴奋脸。首版务必把
> 击杀三档画成明显不同的兴奋脸——早期版本把 `excite_*` 复制成 `normal_*`，导致踩死小人时
> 头像毫无反应，这是必须避免的缺陷。

## 1. 首版 9 张必生格

| 文件 | 编号 | 用途 |
|---|---|---|
| `front_0.png` | P01 | 前爪：抬起最高（空中姿态基准，**露肉垫/鞋底/手套掌面**） |
| `front_3.png` | P02 | 前爪：刚触地（地面姿态基准，**脚背朝上、不露肉垫**） |
| `front_5.png` | P10 | 前爪：最大压力（高压基准，**肉垫仍不可见**） |
| `back_0.png` | P03 | 后爪：远景基准（踩地、不露肉垫） |
| `normal_0.png` | F01 | 表情：开局平静基准脸（`normal_1..5` 全部复用它） |
| `excite_0.png` | F02 | 击杀：ego 0 兴奋脸（必须明显区别于 `normal_0`） |
| `excite_1.png` | F04 | 击杀：ego 1 兴奋脸（明显区别于 `normal_0`） |
| `excite_2.png` | F06 | 击杀：ego 2 兴奋脸（明显区别于 `normal_0`，后期复用它） |
| `endscreen.png` | E01 | 结算横幅 |

**`normal` 列只需一张平静脸**：`normal_0` 即"无击杀时的表情"，`normal_1..5` 全部复用它，
头像在 ego 爬升过程中保持平静。**`excite` 列三档必须明显不同**：`excite_0/1/2` 是"同一张脸
被击杀刺激到"的三档兴奋版（眼睛睁大、眉毛上扬、张嘴笑、脸颊/汗滴/星星等），不能照抄
`normal_0`，也不要三张互相雷同。后期 `excite_3/4/5` 复用 `excite_2`（最高档兴奋脸），保证
后期击杀仍有反馈。
`validate.py` 的 `expression:normal-reuse`（normal 三档相同）只是 **WARN**，是默认设计；
`expression:kill-ego`（击杀帧等于常态帧）会判 **FAIL**。

**肉垫/掌垫可见性（C12，必写进爪格提示词）**：肉垫只在**脚底转向观众**时可见——
`front_0/1/2`（抬起段）可以露；`front_3/4/5`（触地/加压/最大压力）脚底朝下贴地，
**只画脚背、脚侧、脚跟，肉垫被地面遮住、完全不可见**。`back_0..4`（远景踩地）同样不露肉垫。
穿鞋时对鞋底纹路、戴手套时对掌面纹路同理：抬起可见，贴地不可见。

## 2. 占位符

| 占位符 | 内容 |
|---|---|
| `{{OC_DESC}}` | `oc_profile.md` 里的角色长相、配色、物种、画风 |
| `{{FOOT_FIXED}}` | 固定肢体特征。**脚模式**：左右、趾数/趾序/爪垫（裸露时）、**鞋/袜类型、鞋底纹路、鞋带与饰物**、记号、描边色；**手模式（D）**：左右、五指指序/掌纹（裸露时）、**手套类型、掌心缝线/压纹、腕饰**、记号、描边色。参考图若穿鞋/戴手套，以鞋和手套为固定项，不得改成光脚/裸手 |
| `{{FACE_FIXED}}` | 固定脸部特征：脸型、耳形、瞳色、发型、项圈/斑点、描边色 |

| `{{REF}}` | 已生成的同组基准帧（作为参考图上传给模型） |

"已生成帧"，各帧只能共用 OC 参考图，一旦出现串图或姿态不一致，立即回退串行并按此表重生成。

> **手模式词替换**：用户明确说"用手"时，把本文件所有提示词里的
> 脚/爪/脚掌/脚趾/趾数/脚跟/脚底/腿 → 手/手掌/手指/指序/手腕/掌根/掌面/手臂，

## 3. 通用前缀（每条提示词都要带）

```
为 2D 手绘游戏生成【单张独立素材图】，只画一个主体，不要越出画面。
角色设定：{{OC_DESC}}。画风：{{STYLE}}。
背景：纯透明 PNG；若无法输出透明，请用纯白色（#FFFFFF）平铺背景，主体外不要有任何渐变、阴影或环境。
【爪格构图·最重要】脚掌（手模式为手掌）最底部必须紧贴画面底边，与底边之间不得留任何透明空隙（≤2px）；
腿（手模式为手臂）必须是有实体填充的柱状肢体（皮肤/袜子/裤腿），从脚掌向上延伸并超出画面顶边
（在顶边被裁断），腿的内部不透明、与脚掌同色系。禁止只画两条轮廓线，禁止空心、透明、镂空的腿。
透明留白只允许在肢体左右两侧，绝不允许出现在脚底/掌面下方或腿的内部。
禁止把整只脚/手居中摆放，禁止在下方画地面、影子或留白。
【鞋袜/手套·必须照参考图】参考图若穿鞋、穿袜或戴手套，必须画同款：鞋型、鞋底纹路、鞋带/袜子/饰物、
手套材质与掌心缝线在 11 个爪格中完全一致。禁止擅自改成光脚/裸手、禁止中途脱掉，
禁止为了"露出脚底/掌纹"把鞋或手套画破或移除。此时"露出脚底"改为露出**鞋底（鞋底纹路、鞋跟）**，
手模式改为露出**手套掌面（掌心缝线/压纹）**；趾数、掌纹只在裸露时才作为固定项。
本文件所有「脚掌/脚底」在穿鞋时一律指鞋底、戴手套时一律指手套掌面，构图与贴底边要求不变。
【表情格构图】头像居中，占画面约 80%，上方留少量透明边。
严格禁止：文字、水印、边框、圆角框、UI 元素、投影、多余人物、多余肢体、第二只脚/手、镜像翻转、随机花纹变化；
手模式下额外禁止脚趾、脚跟、爪垫、蹄子。
构图比例：爪格为竖版 5:8，表情格为正方形 1:1，结算横幅为横版 2:1。
参考图 {{REF}} 只用来对齐长相与同组基准姿态；禁止改变 {{FOOT_FIXED}} / {{FACE_FIXED}} 中任何固定特征。
```

> 游戏把爪格底边当作脚底位置，碰撞判定完全不看图片内容；脚底留白会让脚看起来悬空、
> 小人却已被踩死。脚本层还会再自动裁剪+底对齐兜底，但提示词必须先把这件事说清楚。

## 7. 复用映射（首版自动生效，无需生成）

| 复用格 | 复制自 | 代价 |
|---|---|---|
| `front_1`、`front_2` | `front_0` | 抬爪过程不做渐变 |
| `front_4` | `front_5` | 中压与高压同图 |
| `back_1..4` | `back_0` | 后爪不随压力变化（这些帧本就极难出现） |
| `normal_1..5` | `normal_0` | 无击杀时头像始终平静，不随 ego 升级（默认设计） |
| `excite_3`、`excite_4`、`excite_5` | `excite_2` | 后期击杀复用最高档兴奋脸，仍有反馈 |
| `tired_0`、`tired_1` | `normal_0` | 疲惫状态用平静脸，两帧无眨眼差 |

**无击杀时（`normal` 列）复用一张平静脸；击杀（`excite` 列）在 ego 0/1/2 三档各自独立、
明显变化，后期复用最高档。** 代价：normal 不随 ego 递进（可在第 9 节补 `normal_1/2`）、
疲惫无眨眼、抬爪/加压/后爪压力无渐变，均在第 9 节候选里，用户需要再补图即可。

## 8. 生成批次与并发

1. **默认尝试并发**：把 9 张必生格的提示词一次性提交给生图通道（若支持批量/并发），
   用并发缩短等待时间。
2. **回退规则**：若生图通道不支持并发、报并发限制或并行结果互相串图，
   立即改为逐格串行生成，**其余流程一律不变**（不改合成、校验、导入步骤，也不重新设计提示词）。
3. 串行时顺序：`front_0` → `front_3` → `front_5` → `back_0` → `normal_0` → `excite_0`
   → `excite_1` → `excite_2` → 横幅；每格按第 2 节「`{{REF}}` 上传表」
   把同组基准帧作为参考图上传，
   不要跳过上传，也不要只用文字描述代替参考图。
4. 输出统一命名 `frames/<cell>.png`，且必须是 **8-bit 非隔行 PNG**（RGBA/RGB/调色板均可）。
   尺寸不精确没关系：爪格由 `build_sheet.py` 裁掉透明边后**底对齐**贴入，表情格与横幅等比居中贴入。
   各帧尽量都用 5:8 竖版，避免包围盒比例差异过大导致脚被独立缩放。
5. 模型不支持透明输出时统一指定纯白底，合成保持默认 `--bg auto`（自动估背景色）；
   仅当自动估色失败才显式 `--bg white/green/...`。不要混用多种底色。

## 9. 补细节（用户确认后再做）

**首版复用的可见损失（交付时必须主动告知用户）**：无击杀时（`normal` 列）复用一张
平静脸，头像不随 ego 升级；击杀（`excite`）在 ego 0/1/2 三档独立、明显，`excite_3/4/5`
复用最高档。其余代价：`tired_0/1` 同图（无眨眼）、`front_0/1/2`、`front_4/5`、
`back_0..4` 各自同图（抬爪与加压无渐变）。`validate.py` 的 `expression:fast-pass`
会把这些列成一条 WARN，属**预期**，不是错误。

按"可见收益 / 成本"排序，用户可任选若干项，每补一项就多生成对应文件：

| 优先级 | 补哪些格 | 收益 |
|---|---|---|
| 1 | `normal_1` + `normal_2` | 让无击杀时头像也随 ego 升级（不补则始终平静，属默认设计） |
| 2 | `excite_3` / `excite_4` / `excite_5` | 让后期击杀的兴奋也逐档升级（不补则复用最高档） |
| 3 | `front_1`、`front_2`、`front_4` | 抬爪下落与加压渐变更连贯（落地/翻面过渡更自然） |
| 4 | `back_2`、`back_4` | 后爪压力变化 |
| 5 | `tired_0` + `tired_1` | 恢复疲惫眨眼动画 |

补完后重跑：

```
python scripts/build_sheet.py --frames frames/ --base generic.png --bg auto --name "<OC 名字>"
#   不加 --out 时，默认产物落在桌面且文件名自动带角色名 + 时间戳，绝不覆盖旧产物
python scripts/validate.py --sheet custom.png --base generic.png --report custom.report.json
```

`validate.py` 的 FAIL 必须修完再导入；WARN 逐条目检。
`build_sheet.py` 的 report 会标出每格是 `generated` 还是 `reused:<源格>`，便于核对补画是否生效。
